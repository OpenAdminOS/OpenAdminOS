Data policy decides what each model may see, and when masking applies, the answer says what was hidden.

Seven data classes, three provider tiers, three actions. Rules apply on this device before every model call: agent runs, Chat, Office, drafts, follow-ups, Nova, hosted voice context and web search. A masked identity, device or security name or identifier is replaced by a token for the call and restored on the way back, so the admin reads real names while a hosted model sees placeholders. Every other masked value is replaced one way: a credential stays [CREDENTIAL], and masked activity or configuration stays a placeholder, in the answer, the transcript and tool parameters. Check the frames at 1280 and 900 px, in both themes. Click any cell in A to change a rule; the sample line redraws. A stricter action applies at once, a looser one asks first.

    • Block to Mask on Hosted is also a loosening: prompts that were refused start going out, with placeholders. The dialog says so in the same plain words.
    • Credential Block to Mask has its own words, in this dialog, in the matrix and in a reset that includes it: calls that were blocked can now leave this device; values the app recognizes as credentials are replaced one way and never restored; a secret written in free text in a form the app does not recognize may still be sent. The same function writes all three, so the text cannot drift.
    • The refusal card appears once, in Settings, Data policy, the first time the app loads an IT rule stricter than the admin's own setting. The admin's setting is kept on record, so it applies again if IT removes the rule.
