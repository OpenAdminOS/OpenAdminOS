An agent of your own: a name, a way of answering, and only the access you give it.

The personal agent is the one agent that answers in Chat and voice. The admin names it, sets how it answers, grants what it may reach, keeps a library of skills for it and approves everything it learns. Nothing here can grant a change to a tenant: changes still go through agents and diff confirmation. Type a name in A; every mention on this page follows. Check the frames at 1280 and 900 px, in both themes.

          • Decided: in the first version a user-added server offers only the tools the admin approves as read-only at add time. The review opens with every tool unchecked, so nothing is approved by default, and Add server stays disabled until at least one tool is approved. The tool's read-only label from the server is shown in each row but never approves a tool on its own.
          • A tool the server labels as a change is disabled from the start and cannot be approved at all; its row says why. Both frames are live: check and uncheck tools to see the count and the button follow.
          • Decided in round 11: approval needs a positive read-only label. A tool whose annotations have no readOnlyHint, or that sends no annotations at all, such as list_categories, is disabled with "No read-only label from the server". The protocol reads a missing readOnlyHint as false, so the app does too.
          • Decided in round 4: approval needs a read-only label and no documented write behavior. The app flags a tool whose definition describes saving, changing, sending or deleting, such as export_report, which saves a report on the server; a flagged tool is disabled in every review state with the reason under its name, whatever its read-only label. The flag is a check the app makes, not a promise about the server: a write the definition does not mention cannot be detected, which is why approval stays a human decision.
          • Decided in round 11: the admin approves the complete tool object the server lists, not a projection of it. Every row opens with Full definition: a readable view (name, title, description, input and output schemas with every nested property, type, description and allowed value, every annotation including annotations.title, and any other field such as _meta) and, next to it, the raw JSON of the whole object, with the words the write check matched marked in both.
          • The write check walks the whole object and reads every string in it, keys included, at every depth: names, titles, descriptions, nested schema properties, enum values and annotations. baseline_versions, whose name and description only read, is flagged by its title, "List and apply baselines", and by the value apply at inputSchema.properties.mode.enum[1]; the reason names each path.
          • Decided in round 12: tenant_setting is labelled read-only (readOnlyHint: true), but its description says "Edits the selected tenant setting", so it is flagged and cannot be approved in the first review. The label never outweighs a write the definition documents.
          • The approval is bound to the JCS SHA-256 hash of the whole object: the object in the RFC 8785 JSON Canonicalization Scheme (JCS), then SHA-256 over its UTF-8 bytes. JCS sorts object keys by UTF-16 code units at every level and writes numbers and strings in its own fixed form. The raw view prints that order. search_settings carries _meta keys "10" and "2", and "10" comes first, as JCS requires. Before a tool is offered and again at every call, the app hashes the object the server lists now; any difference anywhere, a nested schema property, annotations.title, _meta or a field the app does not know, invalidates the approval. Each row shows the short form of the hash; the definition shows the full hash with Copy.
          • Decided in round 14: the readable view shows the same complete object as the raw JSON, nothing only in one of them. Every other field is written out with its nested values (both _meta keys of search_settings and the two page sizes under contoso.example/pageSizes, in JCS order), and each input and output schema shows its own type and every keyword, on the schema, on each property and on array items, with its value.
          • Decided in round 15: one recursive layout reads every schema node at any depth, the root, each property, array items and items of items. A keyword it lays out (a string description, an enum list, properties, required names, a single items schema) gets its own line; every other keyword, and any keyword in another shape, is written out with its value. list_platforms shows both: its input schema has a root enum whose only value is an empty object, and its output schema has a description at outputSchema.properties.families.items.items.description, "A platform id, such as windows10", in the readable view as in the raw JSON.
          • Decided in round 16: an enum value that is not a string, such as the empty object here or {"mode": "apply"}, is written out by the same path-aware value renderer as any other nested value, so a re-review that changed inputSchema.enum[1].mode marks that key in the readable view and in the raw JSON alike. A required name counts as present only when the schema's properties has it as its own key: a name such as constructor is listed as required with no property, never found on the object prototype.
          • The write check and the hash on this page are scripts that illustrate the plan, which governs (B5, Your own MCP servers). The write check here matches a short word list: save, change, send, delete, edit, update, modify, set, write, create, assign, remove, revoke and similar words. The implementation treats any write the definition documents as disqualifying, whatever words it uses and whatever its read-only label says. The hash here is a small JCS serializer and SHA-256, the same rule the plan names.
          • A tool that is not approved is never offered to the model. The approval is checked again at every call, whether it comes from Chat, a skill or a scheduled check, so a skill that names mcp__policy-settings__export_report cannot use it.
