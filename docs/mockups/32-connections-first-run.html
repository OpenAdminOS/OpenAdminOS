32 · Connections and first run

Start with a model. Connect services when a question needs them.

A fresh install no longer asks the admin to sign in, pick sample data, or skip. Chat opens and works for anything that needs no tenant data: docs, KQL, scripts, release notes, end-of-life dates. Microsoft 365 is one connection among several, asked for at the moment a question or agent needs it.

The scope in the top bar becomes an organization: the company the admin manages, with whatever services it runs.

Write a KQL query for failed sign-ins in the last 24 hours, grouped by user and error code
Searched KQL Search for "failed sign-ins by user and result type" www.kqlsearch.com
Read SigninLogs schema on Microsoft Learn learn.microsoft.com

Failed sign-ins are rows in SigninLogs with a non-zero ResultType. This groups them per user and error, newest first:

SigninLogs
| where TimeGenerated > ago(24h)
| where ResultType != "0"
| summarize Failures = count(), LastFailure = max(TimeGenerated)
    by UserPrincipalName, ResultType, ResultDescription
| sort by Failures desc

Error 50126 is a wrong password and 50074 means MFA was required, so filter those out if you only want sign-ins that were blocked.

Sources: kqlsearch.com community query, learn.microsoft.com SigninLogs reference
