Reset OpenAdminOS

A full local reset for an admin who hands the device on, starts over, or uninstalls. Removing the app bundle alone leaves the data folder, the Keychain item and the token caches, so a reinstall would sign straight back in.

The reset runs in two phases so nothing is deleted while Chromium, SQLite or MSAL hold files. The running app signs out of every organization, stops background work and restarts. The next launch removes the data folder before anything opens it, then shows first run.

  • The button enables only on an exact match, capitals included. The main process checks the phrase again before it starts.
  • When the window is short, the lists scroll and the phrase, field and buttons stay pinned at the bottom. Escape and the scrim close the modal while it is idle.
  • On Windows the subtitle is %APPDATA%\OpenAdminOS and the Keychain line is left out. In a dev build it is the folder in OPENADMINOS_USER_DATA_DIR when that is set.
  • A write run that is applying changes blocks the reset. The modal then shows state 4 with the reason "a write run is applying changes in Contoso. Wait for it to finish".
3

Resetting

After Reset and restart: the pending reset marker is written, every organization is signed out, the scheduler, login item, gateway and MCP servers stop, then the app quits and starts again.

Reset OpenAdminOS

Permanent local deletion
~/Library/Application Support/OpenAdminOS
Signing out of every organization and stopping background work. OpenAdminOS closes in a moment.
  • Close, Escape, the scrim, Cancel and the field are disabled. The button keeps full contrast with its spinner instead of the 40% disabled look, so it does not read as broken.
  • Shutdown is awaited with a time limit. If a step hangs, the app still restarts and the wipe at the next launch does the rest.

The reset could not start

Shown only when nothing changed, for example when the marker could not be written. The phrase stays filled, so trying again is one click.

Reset OpenAdminOS

Permanent local deletion

The reset could not start: the data folder is read-only. Nothing was removed. Try again, or quit OpenAdminOS and remove the data folder by hand (see Uninstall and reset in the docs).
  • The reason is the user-facing one from the main process, never a raw stack. Other examples: "the data folder could not be written (disk full)", "a write run is applying changes in Contoso. Wait for it to finish".
  • The alert sits above the buttons, where the eye is after a click. It clears on the next attempt.

Reset did not finish

Shown at the next launch instead of the app when items in the data folder could not be removed. No sidebar, no organization, no store is open. The marker stays, so the reset resumes at every launch until it completes.

Try again restarts OpenAdminOS and removes what is left. To remove the folder by hand, quit and follow Uninstall and reset in the docs.

  • Show data folder opens Finder or File Explorer at the folder. Quit closes the app; the reset resumes at the next launch.
  • Only data folder failures land here. Leftovers outside the folder (Keychain item, scheduler task, updater caches) go to the first-run notice in 6b and are not retried, so a later retry cannot delete the new Keychain key.
  • policy.json is never in this list: it is kept on purpose.
