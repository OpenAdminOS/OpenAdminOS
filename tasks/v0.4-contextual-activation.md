# v0.4 contextual activation

Status: implemented and verified. Fable final verdict: SHIP.

## Decision

OpenAdminOS opens directly into the real Chat-first desktop shell. Tenant and provider setup is contextual activation, not a blocking welcome tour. Users can understand the product, browse its main surfaces, select a suggested question, and edit a local draft before deciding to connect a tenant.

This keeps the product useful before commitment without relaxing the hard runtime rule: no Graph-backed Chat, cache refresh, Changes data, or agent run starts without an active tenant.

## Fable plan

### P0 — Change the front door

- Remove the zero-tenant redirect from `App.tsx`.
- Route `/`, `/chat`, and the legacy `/onboarding` path to the normal Chat shell.
- Keep the navigation layout stable when tenant state changes.
- Keep Chat suggestions enabled for guests; selecting one fills the composer and never sends automatically.
- Make the status strip and tenant switcher clear, persistent connection entry points.

### P0 — One contextual setup controller

- Add a renderer-level provider around the app shell.
- Expose `requireTenant`, `requireTenantAndProvider`, and `openSetup`.
- Gate Chat Send, agent runs and reruns, schedule run-now actions, command-palette runs, Changes activation, and explicit tenant connection through that controller.
- Reuse the existing modal focus trap, Escape stack, focus return, and button primitives.

### P0 — Permission and sign-in flow

- Load the requested scope list from the desktop host so UI and MSAL cannot drift.
- Group the 16 initial read scopes into Devices and configuration (6), Apps (2), Users/groups/directory (4), and Security/sign-ins (4).
- Preserve unknown future scopes in a visible Other group.
- Explain system-browser sign-in, operating-system credential protection, standard sign-in scopes, beta Graph reads, and per-agent incremental write consent.
- Provide Cancel at every nonterminal step.
- Show a soft waiting recovery state after 180 seconds and stop the host listener after 300 seconds.

### P0 — Resume safely

- Store only pending-action metadata in `sessionStorage`: action kind, local return route, conversation id, agent slug, validated resource kind, optional run pinning, scheduled batch mode, and creation time.
- Keep Chat content exclusively in the existing local draft store.
- Validate pending intent shapes, reject external routes and unknown fields, and expire intents after 30 minutes.
- After successful setup, show an explicit action such as Send your question, Review agent run, or Open Changes.
- Never auto-send or auto-run after sign-in.
- Cancel discards the pending intent but preserves a Chat draft.

### P1 — Provider readiness

- If a pending Chat or agent action has a tenant but no working provider, open the provider step directly.
- Reuse provider status and the existing local/hosted trust model.
- Show actionable Ollama install/start/recheck instructions and setup links for other providers.
- Allow explicit tenant connection to finish without configuring a provider.

### P1 — Auth cancellation and recovery

- Add a cancel IPC from renderer to host.
- Supply MSAL with a custom loopback listener that supports `AbortSignal` and a bounded timeout.
- Close the HTTP listener on cancel, timeout, server failure, and MSAL completion.
- Ignore a late cancel once an authorization code has arrived so a successful connection can still persist.
- Humanize cancellation, timeout, consent, account, tenant, and network errors without hiding the original fallback signal.

### P1 — Accessibility and responsive behavior

- Use native buttons and form controls with visible focus states.
- Give scope disclosures `aria-expanded` and `aria-controls`.
- Announce waiting, timeout, provider, error, and ready transitions through a polite live region.
- Keep modal actions outside the scroll region.
- Stack actions below 720 px and contain long scope names and errors.
- Respect reduced motion for waiting indicators and existing app transitions.

### P1 — Verification

- Unit-test pending-intent validation, expiry, and safe storage.
- Unit-test every default scope mapping and unknown-scope fallback.
- Unit-test MSAL listener cancellation and hard timeout.
- Renderer-test guest suggestion → editable draft → Send → setup, with no early Graph or LLM call.
- Run workspace typecheck, tests, Graph QA, docs checks, build, and Electron smoke.
- Inspect desktop layouts at wide and constrained sizes.
- Ask Fable to review the complete diff and fix all blocker/high findings.

Final Fable scores: correctness 9, trust and security boundaries 9.5, resume and state safety 9, error handling and recovery 9, accessibility 9, test coverage 9, copy and voice 9, architecture and spec alignment 9, and maintainability 8.5. Final verdict: SHIP, with all remaining low-severity hygiene notes addressed after sign-off.

## Acceptance criteria

- A fresh profile opens Chat without a tenant.
- All main destinations remain browsable and the side navigation does not move.
- Suggested questions only populate an editable draft.
- Tenant-backed actions open the same setup dialog and cannot bypass it.
- Permission copy matches the host's actual requested scopes.
- Cancel and timeout close the local callback listener.
- No prompt text, token, key, or tenant content is added to pending-intent storage.
- Successful sign-in never sends or runs without one final explicit click.
- Existing tenant, provider, chat, run, registry, and update state remains backward compatible.
