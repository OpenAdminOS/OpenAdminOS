# v0.4 quality gap closure: copy, interaction, accessibility

**Status: implemented; manual evidence pending.** This is not a second roadmap and adds no new product surface. It strengthens the existing round-two phases with shared machinery, tests, and release evidence.

| Category | OpenAdminOS baseline | v0.4 target |
|---|---:|---:|
| UX writing | 7.5 | **≥ 9.2** |
| Interaction polish | 7.5 | **≥ 9.2** |
| Accessibility and responsive behavior | 7.5 | **≥ 9.0** |

The targets apply to the implemented v0.4 desktop experience, not only to mockup 13. A score increase requires the evidence in the score gate below; reviewer confidence alone is insufficient.

## Relationship to the round-two plan

The round-two plan remains authoritative for product scope, routing, the stable rail, progressive Chat, trust-message placement, searchable Settings, Agents, and release sequencing. The gap-closure phases interleave with it:

| Gap phase | Round-two dependency |
|---|---|
| G0 — Baseline evidence | After round-two Phase 0 decisions |
| G1 — Copy architecture | After the mechanical split in Phase 1; feeds Phases 4, 5, 6, and 8 |
| G2 — Shortcuts and overlays | With Phase 3; before Phase 7 keyboard work |
| G3 — Composer state machine | With Phase 4 |
| G4 — Settings search quality | Extends Phase 6 |
| G5 — Accessibility and responsive invariants | Extends Phase 7 |
| G6 — Evidence pack and re-score | Extends Phase 9 |

If a task overlaps, the round-two phase absorbs the work. This document supplies the stricter behavior and evidence criteria.

## Non-negotiable constraints

- The active tenant remains visible at all times.
- Local-provider tenant data and prompts remain on the device.
- Hosted-provider copy names the provider and verified destination honestly.
- Every write pauses for review; destructive writes retain typed confirmation.
- Retry never bypasses hosted consent, tenant scope review, or write confirmation.
- No new product, prompt, tenant, result, error-payload, or timing telemetry.
- No T3-style Full access or AI-approved permission mode.
- No hover-only critical action, web/mobile surface, or terminal-centric interaction model.
- No new Graph endpoint, permission, or write contract.

## Diagnosis

### UX writing: 7.5 versus 8.5

The product voice is already stronger than the enforcement behind it. Copy and trust strings are authored at call sites, Settings/search labels are not guaranteed to round-trip, agent names can differ between cards and run history, and no test rejects generic errors or canonical trust-string drift. T3 is ahead because important labels and descriptions are stored in small tested catalogs.

### Interaction polish: 7.5 versus 9.0

The current app has useful individual behaviors but no shared keyboard model or overlay discipline. `Modal.tsx`, `CommandPalette.tsx`, Chat, and the rail each own parts of Escape, focus, and selection behavior. Chat can stop work but has no complete retry and draft-restoration model. T3 is ahead because shortcuts, draft persistence, submission rules, and recovery decisions live in focused pure modules with unit tests.

### Accessibility and responsive behavior: 7.5 versus 8.0

OpenAdminOS already has visible focus, multiple live regions, status roles, and accessible labels. The remaining gap is systemic: reduced motion does not cover every global animation, dialog semantics and focus trapping are incomplete, informative text can fall below the intended floor, forced-colors behavior is undesigned, truncation relies too heavily on hover, and the screenshot harness does not enforce multiple desktop widths or horizontal-overflow limits.

## G1 — Typed copy architecture and consistency tests

**Outcome:** make copy consistency a tested implementation property rather than a review convention.

### Likely files

- New `apps/desktop/src/copy/`
- `apps/desktop/src/shared/agent-display.ts`
- Post-split `apps/desktop/src/pages/chat/`
- Post-split `apps/desktop/src/pages/settings/`
- `apps/desktop/src/components/StatusStrip.tsx`
- `apps/desktop/src/components/TrustBanner.tsx`
- `apps/desktop/src/components/CommandPalette.tsx`
- `apps/desktop/src/components/RunFailureRemediation.tsx`
- New copy tests under `apps/desktop/src/copy/`

### Proposed module layout

```text
apps/desktop/src/copy/
  index.ts       public barrel
  common.ts      stable verbs, actions, status labels
  chat.ts        headline, examples, composer, transcript labels
  settings.ts    section and row titles/descriptions
  agents.ts      outcome, Run/Review, suggestion copy
  trust.ts       derived local/hosted boundary copy
  errors.ts      typed recovery copy
```

Stable UI copy comes from these modules. Dynamic tenant, provider, model, count, and resource values remain typed arguments. Do not add an i18n framework for v0.4.

### Canonical trust copy

Add one pure derivation function:

```ts
deriveTrustCopy({ provider, scope, attachments }): {
  strip: string;
  boundary?: string;
  confirmTitle: string;
  confirmBody: string;
}
```

- `strip` supplies the persistent StatusStrip value.
- `boundary` appears only for hosted providers or non-default attached context, following round-two Phase 5.
- Confirmation text names the provider, verified destination, tenant or tenant list, and included workspace evidence.
- StatusStrip, onboarding, Chat, hosted consent, multi-tenant batch consent, and connector confirmation consume this derivation.
- Tests prove that canonical local/hosted strings are not duplicated outside `copy/trust.ts`.

### Agent-name round-tripping

Extend `shared/agent-display.ts` as the single display-name formatter. Agent cards, Chat suggestions, Command Palette entries, Run Result, run history, and notifications must consume the same formatter. A rendering test mounts all surfaces with one fixture agent and asserts the same display name.

### Error copy grammar

```ts
interface AppErrorCopy {
  what: string;
  why?: string;
  action: {
    label: string;
    kind: "retry" | "navigate" | "external" | "instruction";
  };
}
```

- `what` states the specific failure.
- `why` appears only when the cause is known.
- `action` always supplies a working recovery path.
- Chat, Settings, agent runs, provider checks, preflight, and `RunFailureRemediation` use the same rendering pattern.
- Generic "Something went wrong" states remain forbidden.

### Tests

- Catalog keys are unique and values are non-empty.
- Interpolation functions accept every supported provider/scope state.
- Catalog copy rejects agreed banned phrases, hype adjectives, emoji, and exclamation-mark sentence endings.
- A targeted source scan rejects hardcoded canonical trust phrases outside `copy/trust.ts`.
- Every error-copy entry has a non-empty recovery action.
- Settings catalog titles round-trip through the rendered row, search result, and Command Palette.
- Agent names round-trip across all six surfaces.

Do not scan raw TypeScript operators for punctuation. Voice checks apply to catalog strings and explicitly identified JSX copy, with a narrow reviewed allowlist where necessary.

### Acceptance criteria

- All stable production UI copy touched by v0.4 is catalog-backed.
- Trust copy has one derivation path.
- Every designed failure state has what/why/action copy and a functioning action.
- Changing one agent or Settings title updates every consumer without a second literal.
- The cleaned mockup copy deck is reflected in production and screenshot baselines.

**Expected score movement:** UX writing +0.9; accessibility +0.1.

### Suggested commits

- `ui: extract stable user-facing copy into typed modules`
- `ui: derive trust messaging from one source`
- `ui: standardize recoverable error copy`
- `qa: enforce copy consistency and round-tripping`

## G2 — Interaction foundation: shortcuts and overlay stack

**Outcome:** one keyboard model and one focus/Escape model across the application.

### Likely files

- New `apps/desktop/src/shared/shortcuts.ts`
- New `apps/desktop/src/shared/shortcuts.test.ts`
- `apps/desktop/src/components/Modal.tsx`
- New `apps/desktop/src/components/overlay.tsx`, or equivalent logic inside the shared Modal foundation
- `apps/desktop/src/components/CommandPalette.tsx`
- `apps/desktop/src/components/AppShell.tsx`
- `apps/desktop/electron/main.ts`

### Shortcut registry

- Define a typed command registry with platform-aware labels and `when` contexts such as `composerFocused`, `inputFocused`, and `overlayOpen`.
- Initial proposed map, subject to approval:
  - `Mod+K`: Command Palette
  - `Mod+N`: New conversation
  - `Mod+,`: Settings
  - Enter: send from the composer
  - Shift+Enter: insert a line break
  - Arrow keys, Home, End, Enter: rail and palette navigation
  - Escape: close the topmost overlay only
- Electron menu accelerators, palette hints, and tooltips consume the same registry.
- Do not copy T3's terminal, preview, thread-number, or permission-mode shortcuts.

### Overlay model

- Register modals, palette, menus, disclosures, and the narrow rail in a single ordered stack.
- Escape closes only the topmost overlay and never confirms an action.
- Each overlay declares its scrim-click policy.
- Shared Modal supplies `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, initial focus, focus trapping, and focus return.
- Typed-confirmation input is never prefilled and is cleared when the modal closes.
- Destructive confirmation can close without acting via the approved Escape/scrim policy; closing can never apply the change.

### Command Palette semantics

- The input uses combobox semantics with `aria-expanded` and `aria-activedescendant`.
- The result collection uses listbox/option semantics.
- Arrow keys, Home, End, Enter, and Escape are tested.
- Empty results and invalid/deleted destinations have designed recovery states.

### Tests and verification

- Platform label and `when`-context tests for every shortcut.
- Menu accelerator and registry agreement test.
- Nested-overlay test proving topmost-only Escape.
- Focus trap, initial focus, and focus-return tests.
- Command Palette keyboard and semantic-role tests.

### Acceptance criteria

- No independent global Escape handler remains outside the overlay manager without a documented exception.
- Every visible shortcut label is derived from the registry.
- Every overlay traps or scopes focus correctly and returns it to the invoker.
- Palette operation is complete without a pointer.

**Expected score movement:** interaction +0.7; accessibility +0.4.

### Suggested commits

- `ui: add a typed platform-aware shortcut registry`
- `ui: add overlay priority with focus trap and return`
- `ui: give the command palette complete combobox semantics`
- `desktop: align menu accelerators with the shortcut registry`

## G3 — Composer state machine: send, stop, retry, drafts

**Outcome:** no lost draft and no dead-end Chat failure.

### Likely files

- Post-split `apps/desktop/src/pages/chat/Composer.tsx`
- Post-split `apps/desktop/src/pages/chat/MessageList.tsx`
- Post-split `apps/desktop/src/pages/chat/IntuneChat.tsx`
- New `apps/desktop/src/shared/chat-send-state.ts`
- `apps/desktop/src/pages/IntuneChat.test.tsx`
- `apps/desktop/electron/intune-chat/service.ts` only if retry metadata is not already persisted
- `scripts/smoke-intune-chat.mjs`

### State model

Implement a pure reducer with an explicit transition table:

```text
idle → sending → streaming → complete
                         ↘ stopped
                         ↘ failed → retrying
```

Invalid transitions fail tests rather than being silently ignored.

### Behavior

- Enter submits and Shift+Enter inserts a line break through one tested policy function.
- Streaming exposes Stop; the UI shows Stopping until the host acknowledges.
- Stopping keeps partial output and labels it clearly.
- Failed responses retain the original prompt, scope, tenant, and attachment references and expose Retry.
- Retry re-runs every applicable hosted consent, tenant scope, and workspace-context boundary.
- Per-conversation drafts persist locally and restore on route return; successful send clears the draft.
- Prefer the existing SQLite/IPC conversation path when it can carry drafts without a new broad contract. Otherwise use local `sessionStorage` for v0.4 and record SQLite persistence as follow-up.
- One polite live region announces lifecycle boundaries once: sending, streaming, complete, stopped. Failures use an assertive announcement. Never announce every streamed token.

### Tests and verification

- Reducer transition-table tests.
- Enter/Shift+Enter submission tests.
- Stop preserves partial output.
- Failure exposes Retry without retyping.
- Retry reopens hosted and multi-tenant consent when required.
- Draft survives route navigation and remains local.
- Existing hosted-consent, write-intent, tenant-scope, and related-agent tests remain green.
- Extend smoke coverage with stop/retry if the existing driver can inject a provider failure; otherwise add a focused renderer integration test and record the limitation.

### Acceptance criteria

- Every Chat failure is recoverable in one action.
- Retry cannot bypass any safety boundary.
- Draft text is restored locally and never sent before Send.
- Screen-reader announcements are bounded and meaningful.

**Expected score movement:** interaction +0.5; UX writing +0.2; accessibility +0.2.

### Suggested commits

- `ui: model chat send state as a tested reducer`
- `ui: add safe retry for failed chat sends`
- `ui: persist conversation drafts locally`
- `ui: announce chat lifecycle without token noise`

## G5 — Accessibility and responsive invariants

**Outcome:** convert round-two Phase 7's checklist into enforceable tests and cross-platform release checks.

### Likely files

- `apps/desktop/src/styles/globals.css`
- `apps/desktop/src/components/StatusStrip.tsx`
- `apps/desktop/src/components/Pill.tsx`
- New `apps/desktop/src/components/TruncatedText.tsx`
- `apps/desktop/src/components/AppShell.tsx`
- Route components requiring landmark cleanup
- New focused style/invariant tests
- Screenshot harness from G0

### Text floors

- Informative body text: at least 12 px.
- Secondary metadata: at least 11 px.
- Decorative monospace labels may use 10 px.
- Raise StatusStrip informative values to at least 11 px.
- Add a narrow allowlisted source check for sub-floor utility classes and inline values.

### Contrast

- Add a small dependency-free WCAG contrast test for actual informative token pairs on background, elevated background, and surface.
- Require at least 4.5:1 for informative text.
- Restrict `--color-text-faint` to disabled or decorative use unless its contrast passes.
- Any canonical token change requires approval and must update production tokens and relevant design references together.

### Motion

- One global reduced-motion block disables or neutralizes fade, fade-scale, pulse, shimmer, transform hover, and layout transitions.
- JavaScript scrolling and focus highlighting use instant behavior when reduced motion is active.
- Streaming autoscroll and Settings highlight both respect the preference.

### Forced colors and zoom

- Add `@media (forced-colors: active)` treatment for text, borders, Pills, selected rows, diff states, and focus outlines.
- Verify Windows High Contrast manually.
- Verify 125% and 150% Electron zoom at 1100 px without clipped controls or unusable StatusStrip content.

### Semantics and announcements

- Exactly one primary navigation landmark and one main landmark per route.
- StatusStrip is a labeled footer/status region.
- Shared dialog semantics come from G2.
- Chat lifecycle announcements come from G3.
- Existing Settings save and run-progress announcements use catalog-backed strings.

### Truncation disclosure

Add `TruncatedText` so the full tenant, conversation, workspace, agent, or model value is available through keyboard focus and assistive technology, not only a hover `title`. Apply it first to StatusStrip tenant/provider values and conversation rows.

### Width and long-content matrix

- Run every G0 route at 900, 1100, and 1600 px.
- Assert no page-level horizontal overflow.
- Keep wide Chat artifacts inside their own scroll container.
- Test long tenant, conversation, and model values.
- At the narrow breakpoint, the rail becomes an accessible overlay and returns focus to its trigger.

### Cross-platform manual checks

- Windows High Contrast.
- 125% and 150% zoom.
- Keyboard-only first question, tenant switch, Settings search, and hosted consent.
- Platform-correct shortcut labels.

### Acceptance criteria

- Text-floor, token-contrast, landmark, and reduced-motion tests pass.
- Forced-colors mode preserves state and focus differentiation.
- Every truncated critical value has a focusable full-value disclosure.
- Width matrix and long-content fixtures have zero application-level overflow.

**Expected score movement:** accessibility +0.8; interaction +0.2.

### Suggested commits

- `ui: honor reduced motion across animation and scrolling`
- `ui: enforce informative text floors`
- `ui: add accessible truncation to status and navigation values`
- `ui: support forced-colors mode`
- `qa: enforce contrast landmarks and responsive widths`

## Decisions and approvals required

1. **Round-two Phase 0:** approve or amend its six blocking product decisions.
2. **Canonical trust grammar:** approve exact local and hosted strip, boundary, and confirmation templates. Hosted region text must come from verified provider configuration rather than a guessed default.
3. **StatusStrip:** approve the persistent data-residency cell and 11 px minimum informative text. This aligns with the existing design-system intent but changes a persistent surface.
4. **Shortcut map:** approve `Mod+N`, `Mod+,`, and whether the Help menu should list shortcuts. Recommendation: menu listing, no separate shortcut overlay.
5. **Typed-confirmation close behavior:** approve whether scrim and Escape close without acting. Recommendation: both close without applying; typed input is cleared.
6. **CI voice rules:** approve the catalog phrase/style rules that will fail tests.
7. **Draft storage:** prefer existing SQLite/IPC storage when narrow and available; otherwise approve local `sessionStorage` for v0.4.
8. **Token adjustments:** approve any canonical token change required by the contrast test.
9. **Dependency stance:** no dependency is required. `axe-core` or `vitest-axe` may be considered later, but this plan recommends the existing test infrastructure for v0.4.
