## Integration constraints

- Minimum stable versions: Copilot 1.0.83; Gemini 0.59.0. No additional application dependency or stored API key is introduced.
- Gemini has no auth-status command. It shows Test required until an actual request succeeds in the current app process; repeat the test after restarting before using it for unattended runs.
- Copilot models come from the account catalog; Gemini uses its CLI's configured default.
- Native CLI tools, hooks, skills, extensions, project instructions, and MCP execution are disabled. App-controlled actions retain their existing review flow.
- Vendor CLIs may retain local session history; the adapters remove their own temporary working/configuration directories.
- Windows cleanup originally raced process shutdown and failed with a locked working directory. Waiting for Copilot process exit fixed the native regression.

## Broader Nova command routing review

The next review found separate failure classes beyond leading fillers: unfamiliar verbs bypassing the action handler, incomplete voice delegation, app capability questions routed as generic research, missing channel context on follow-ups, discarded report context on destination corrections, approval utterances dismissing the preview, cancellation variants, and named/multiple destinations being mistaken for defaults.

- A shared typed router now handles direct routes, with one selected-provider JSON classification for unfamiliar wording. Only allowlisted destinations, pages, and installed agent slugs are accepted. Classification cannot execute tools. Uncertain, malformed, timed-out, or unsupported commands get clarification.
- Preview context is bounded and expires. A correction generates a new preview; the old action ID cannot execute. Saying yes preserves the current preview without approving it. Stop and cancellation clear pending interpretation/action context.
- The hosted transcript fallback now handles substantive requests and clarification replies even without model delegation. Known waiting chatter and greetings do not replace pending work.
- Common inventory queries retain their direct cache path. Classification receives the request and bounded agent/clarification metadata, not tenant records or full reports. It uses the already selected provider, a 15-second deadline, and local/hosted scope checks before and after completion.
- 101 focused command/service/action tests passed natively on Linux, macOS, and Windows. The complete Nova suite, including the provider boundary and SQLite device workflow, passed on Linux. Full desktop/backend and renderer suites passed; structural QA remains 182 pass, 4 warnings, 0 failures.
- The manual live corpus in `scripts/verify-nova-command-routing.ts` passed 12/12 with the actual signed-in Codex adapter on Linux, macOS, and Windows. It tests unfamiliar send/run/navigation wording, connector clarification, destination correction, setup questions, unsupported actions, and research. No mail, message, or agent was actually sent or started.
- The first live pass caught two routing problems missed by fixtures: “messaging” incorrectly taking the research fast path, and a cache-freshness question being classified as navigation. Both were corrected before the successful reruns.

Limits: this is a bounded English regression corpus, not proof of universal natural-language understanding. Unfamiliar wording adds a classifier round trip (roughly 4–9 seconds in these live Codex tests); common queries keep their fast paths. Authenticated classifier testing used Codex, not every supported provider. Remote verification used the current source bundles, not an installed 0.6.3 executable or a new microphone session. No new Graph endpoint or permission behavior was introduced; the delegated mail-verification limitation above still applies.


## Mac transcript follow-up: report content and local reasoning

The tested email transport accepted its payload, but the payload was a model summary referring to absent rows. The noun-first request “Show all the non-compliant devices as a list” now uses the direct SQLite report path. Regression coverage runs that report through Teams destination clarification, unavailable WhatsApp setup, an Outlook speech repair, a replacement request, and a mocked approved send, checking the device names in the final connector payload. No actual message is sent by these tests.

Connector aliases and exact installed names resolve without a model. A split connector fragment can continue an unfinished request. Named Teams channels must match configuration, and delivery commands cannot fall into public research. App counts distinguish Intune catalog entries from detected software. Hosted confirmation transcripts avoid inserting the backend text twice, and waiting chatter receives the latest action/result status.

Live selected-provider verification on the Mac used Ollama qwen3:8b with synthetic commands. Its initial pass exposed a destination correction failure and a named-person request being interpreted as default email; deterministic guards now cover both. The expanded 19-case corpus passes, including the user's command wording and report-reference preservation. Direct cases resolve without an LLM call; unfamiliar requests still depend on the selected model and may take seconds, especially on a cold model.

Read-only Lokka beta verification checked managed-device fields, explicit noncompliant filtering and manual nextLink traversal to completion, and the mobileApps/detectedApps collection shapes and paging. Invalid managed-device fields returned HTTP 400. Lokka's fetchAll helper returned “Invalid array length” for the filtered collection, so the paging verification followed the returned beta links manually. Counts from individual pages were inconsistent on app endpoints; the app's existing complete-snapshot count uses all collected rows. The delegated mail-permission limitation above remains; no Graph write was performed.

Limits: the model corpus is bounded English text, and simulated transcript events do not replace a fresh microphone test of the signed app. Reports remain bounded to 50 matching names and explicitly identify truncation or partial cache coverage. Arbitrary named recipients/channels are not silently supported by a configured-default connector.
