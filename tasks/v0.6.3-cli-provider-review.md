# 0.6.3 CLI provider review

## Scope

Incorporates PR #85 desktop discovery/authentication fixes and adds GitHub Copilot CLI and Gemini CLI through the shared provider boundary. Adds Settings diagnostics and explicit connection testing. No release publication or merge is part of this PR.

## Verified

- Linux full unit/integration and renderer suites passed; targeted CLI tests passed after cleanup/cancellation fixes.
- Native Windows execution of all 10 new provider tests passed: npm launcher resolution without a command shell, framed Unicode streaming, auth/access distinction, blocked tool events, cancellation, truncated output, and temporary-directory cleanup.
- Actual Windows Codex 0.153.4 and Claude Code 2.1.269 were discovered in their standard installation locations and reported signed in through their own CLI checks.
- Actual Linux Codex 0.154.0 reported signed in; Claude Code 2.1.268 reported signed out.
- Actual Copilot 1.0.83 protocol discovery worked on Linux and Windows. Linux account model access was denied; Windows reported signed out. These were displayed as different failures.
- Actual Gemini 0.59.0 discovery worked on Linux and Windows. An explicit completion attempt on each reported signed out without exposing raw CLI logs.
- Typechecking, desktop production build, release identity checks, and existing Agent Team Electron smoke passed. Structural QA: 182 pass, 4 warnings, 0 failures with the installed Graph skill. This is structural validation, not new live Graph endpoint verification.
- Linux Electron screenshot matrix completed 42 captures across three widths and both motion settings.

## macOS verification and live-test limits

- Native macOS arm64 verification passed on macOS 26.6.2. All 10 new-provider protocol tests passed. Actual Codex 0.154.0 was detected through Homebrew and completed a live response. Claude Code 2.1.270 was detected in its standard user installation and completed a live response from the logged-in desktop session.
- Claude reported signed out over SSH because that session could not access the login keychain. The same adapter reported signed in and completed successfully from a temporary GUI-session test job; that job was removed after verification. No reauthentication or credential changes were needed.
- The user confirmed they do not have Copilot or Gemini accounts. Successful authenticated completions for these providers are not verified. Native protocol/streaming/cancellation tests on all three platforms and actual installed-CLI discovery/error tests are the available evidence; these are not presented as authenticated completion tests.
- New provider adapters were tested through their real CLI protocols, but authenticated tenant investigations, Nova reasoning, and scheduled runs using those two accounts remain unverified because those accounts are unavailable. Existing shared Agent Team/runtime tests pass.

## Integration constraints

- Minimum stable versions: Copilot 1.0.83; Gemini 0.59.0. No additional application dependency or stored API key is introduced.
- Gemini has no auth-status command. It shows Test required until an actual request succeeds in the current app process; repeat the test after restarting before using it for unattended runs.
- Copilot models come from the account catalog; Gemini uses its CLI's configured default.
- Native CLI tools, hooks, skills, extensions, project instructions, and MCP execution are disabled. App-controlled actions retain their existing review flow.
- Vendor CLIs may retain local session history; the adapters remove their own temporary working/configuration directories.
- Windows cleanup originally raced process shutdown and failed with a locked working directory. Waiting for Copilot process exit fixed the native regression.
